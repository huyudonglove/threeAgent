# Knowledge Management

Last updated: 2026-06-01

## Default Rule

Project knowledge belongs in this repository under `docs/`.

Use Obsidian as a reading, linking, and personal knowledge-management tool, not as the only home for project-critical documentation.

## Store In `docs/`

- Architecture maps
- Runtime flows
- Domain glossary
- Development guides
- Feature plans
- Review findings
- Decisions that should travel with the code
- Notes that future Codex sessions need in order to work safely

## Store In Obsidian

- Personal learning notes
- Cross-project summaries
- Product ideas that are not yet project decisions
- Long-term AI/Agent research notes
- Reflections, reading notes, and private planning

## Obsidian Usage

Do not store notes inside `D:\Program Files\Obsidian\`. That path is the application install directory.

Recommended usage:

- Open `D:\code\threeAgent\docs` directly as an Obsidian vault when focusing on this project.
- Use `D:\obsidian\agent` as the personal Obsidian vault for Agent-related long-term notes.
- From `D:\obsidian\agent`, link back to files in `D:\code\threeAgent\docs` when project documentation is the source of truth.

## Naming Convention

- Stable project references should use durable names, for example `project-overview.md`, `architecture-map.md`, and `domain-glossary.md`.
- Time-sensitive plans or reviews may include dates, for example `workbench-ux-dev-task-board-2026-05-25.md`.
- Prefer one document per durable topic instead of scattering important context across chat transcripts.
